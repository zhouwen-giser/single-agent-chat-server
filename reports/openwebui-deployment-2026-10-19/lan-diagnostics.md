# 局域网访问排查 — 等待客户端信息

本机入口 `http://127.0.0.1:18084/` 只适用于服务器自身。其他局域网设备应使用
`http://17.26.1.20:18084/`。本轮没有把服务器侧检查通过表述为真实局域网客户端
访问通过，仍需要失败设备的实际 URL、IP 和错误信息来定位。

已知原 IP 经过服务器现有 HTTP 代理返回 502，之前的实际内置浏览器也拒绝该
地址；新增本机回环入口解决的是本机浏览器访问。其他设备是否启用代理、实际
所在网段、是否使用了回环或 HTTPS 地址，均需根据客户端信息确认。

## 下一步定位所需信息

在访问失败的设备执行以下请求，提供返回结果及该设备的局域网 IP。Windows
PowerShell 中使用 `curl.exe` 替换 `curl`，避免命令别名。

```sh
curl --noproxy "*" --connect-timeout 5 http://17.26.1.20:18084/health
```

正常正文为 `{"status":true}`。该测试只为本次请求绕过客户端代理，不改变其
系统代理设置。如果直连成功，则再比较浏览器所用 URL 和代理路径；如果连接
失败，则结合客户端 IP 与一次明确重试期间的入站观测检查路由或网络策略。

本轮是诊断记录，不宣称局域网问题已经修复。

## 超时补充：跨网段回程走代理

用户补充故障表现为超时。按当前前端的回复参数（源 `172.29.0.2:8080`、
入接口 `br-11ed9abdc36d`、TCP）查询内核路由，发现以下差别：

| 示例目的地址（不是已确认的客户端） | 实际回程查询                              |
| ---------------------------------- | ----------------------------------------- |
| `17.26.1.10`                       | `eno4np3`，直接网卡                       |
| `17.26.2.10`                       | `CordC`，table 2022，gateway `198.18.0.2` |
| `192.168.1.10`                     | `CordC`，table 2022，gateway `198.18.0.2` |
| `10.0.0.10`                        | `CordC`，table 2022，gateway `198.18.0.2` |

现有代理的策略规则会将不命中主路由直连前缀的转发流量送入代理表，
因此跨网段客户端可能受其影响。尚未获得实际超时设备的 IP，不能将这些
示例查询认定为本次超时的已证实原因。

另外观察了 80 秒的前端 TCP 连接头，本机 loopback 与 bridge 共记录
78 种头组合、348 个包；没有观察到物理网卡或代理隧道上的前端流量。
该窗口没有确认用户已在失败设备重试，不以“未观察到”推断请求的丢失位置。
没有更改代理、网卡或策略路由。下一步需要实际客户端 IPv4 地址，结合明确
重试期间的入站请求判断是否命中跨网段回程问题。
