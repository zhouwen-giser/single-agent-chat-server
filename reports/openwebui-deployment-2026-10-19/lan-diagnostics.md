## 原因与修复

服务器与客户端不在同一子网。前端容器回复从 `172.29.0.2:8080` 经 Docker
bridge 进入主机，主路由原本只有默认网关能到达该客户端。现有代理规则先查询
主路由并忽略默认路由，再将未命中直连前缀的转发流量送入 table 2022。
因此该客户端的容器回复被送入 `CordC`，而此前本机、同网段或 Docker bridge
来源的请求正常，未覆盖这一失败路径。

在现有 NetworkManager 有线连接中追加一条客户端主机路由：

```text
192.168.1.210/32 via 17.26.1.1 dev eno4np3 metric 100
```

`/32` 主路由能够在代理规则查询时命中，回复恢复经物理网卡和网关发出。
连接为 `Wired connection 4`，UUID `5c4bd62e-d23d-3af6-b735-4aeb965556b3`。
使用 `nmcli device reapply` 应用，没有断开再重连网卡。NetworkManager
`Unsaved=false`、`Flags=0`，说明配置已保存；未执行整机重启演练。

范围是此客户端 IP。没有扩大到整个 `192.168.1.0/24`；对其他目的地址的
代理路径、现有策略规则和网卡 IP / 网关保持原状。

## 现场操作与撤销

本机已完成以下操作。新现场应按其真实客户端、网卡和网关配置，不能直接套用
这些站点参数。先检查 `ipv4.routes`，已有同一路由时无需重复追加。

```sh
nmcli connection modify 5c4bd62e-d23d-3af6-b735-4aeb965556b3 \
  +ipv4.routes "192.168.1.210/32 17.26.1.1 100"
nmcli device reapply eno4np3
```

如需撤销本次路由，仅移除相同条目并重新应用：

```sh
nmcli connection modify 5c4bd62e-d23d-3af6-b735-4aeb965556b3 \
  -ipv4.routes "192.168.1.210/32 17.26.1.1 100"
nmcli device reapply eno4np3
```

客户端 IP 如改变，应根据新地址重新检查回程路径。当前修复不代表其他未验证
子网或互联网入口已完成验收。
