# C01 — exact HTTP negotiation and durable source boundaries

Implementation reuses the existing HTTP client, Grounding Job source and normal composition. New enabled configuration selects the frozen 1.2 pair; explicit 1.1 remains isolated. All four HTTP operations verify the pair. Public request/result/job/capability decoding uses the frozen validator; requests are checked before POST, including original-text digest, full request hash and caller result budget. Job identity checks retain request, message, grounding and Job IDs. Optional capability unavailability is not conflated with unsupported protocol.

Grounding intent JSON now saves the selected pair; authorized revision lookup reads it through the existing scoped Grounding join. Rebuilding with default 1.2 does not change a saved 1.1 source. Unidentified source history fails explicitly instead of being reinterpreted. No schema migration or protocol-conversion registry was added. Driver-boundary tests execute the changed repository methods; they are not real PostgreSQL recovery evidence.

Cancellation durably records intent and the visible pending state before HTTP, keeps the existing command claim until its outcome is recorded, and saves a safe unconfirmed-delivery reason on failure. Source observations stay authoritative; a late command cannot overwrite a committed terminal Run. Transient cancellation failure can be followed by bounded GET. Abort, local observation exhaustion and disconnect do not create a remote cancellation or failure.

Verification commands, exit codes and output hashes are generated in C01.json. AC-007/008 full projection and normal two-turn entry completion remain to be demonstrated in C02/C05; synchronous persistence, asynchronous identity and snapshot deduplication already have real HTTP tests. C02–C06 and their remaining REQUIRED assertions are not declared complete. ENV-001 remains NOT_RUN, real upstream/model/device calls remain excluded.
