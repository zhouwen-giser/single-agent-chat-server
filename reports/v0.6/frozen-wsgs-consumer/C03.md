# C03 — Frozen selections and immutable source revisions

Implemented through the existing main composition and actual Grounding HTTP adapter. Verification is recorded in `C03.json` and its command logs; the ledger is changed only by a successful execution of the phase verifier.

## Changes

- Source proposals have an explicit `GROUNDING_SOURCE_QUERY` DTO, without invented native Plan/node/patch identities. Saved Choice interventions use the existing resolve route and exact five-field public selections.
- `analysis_control_command` and the existing session mutation claim provide scope, parent Revision CAS, fencing, conflict and completed/failed replay. Migration 0020 only extends command-kind constraints and its partial uniqueness index; no new queue or platform.
- The canonical next request is saved in the existing Grounding row in the claim transaction, before any HTTP request. Its compact immutable intent carries parent revision/run and command identity. Full user text is not duplicated into the 4 KiB intent.
- A successful source binding atomically inserts the next revision/run, links the new source, closes the selected old intervention, advances the session and completes the command. Published prior results and run lineage remain saved.
- GET/replay/recovery use saved protocol and request identities. Deterministic HTTP rejections end only the local command and release its mutation claim; uncertain transport outcomes remain recoverable. Neither invents a remote FAILED status.
- Recovery uses the actual revision/run terminal observation receipt, not the mere existence of an old projection. Superseded late results update only their historical run/audit; current projection and new run are not overwritten.
- Chat, AG-UI START and Control share the request planner and durable command path. RECONNECT only observes. The shared pump restarts per revision and detaches aborted observers without cancelling source work.
- Chat carries the internal principal resolved by persistence through World/context/message storage; existing SDAR continues to use the external JWT subject. Both Chat→AG-UI and AG-UI→Chat are tested, including deliberately different internal/external identities.
