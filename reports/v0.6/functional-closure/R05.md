# R05 进程故障、断库与并发恢复

R05 完成 FC-18–FC-22，并修复实际复现的断库退出问题：LangGraph PostgresSaver 原本通过 fromConnString 建立独立 pool，空闲连接在 PostgreSQL restart 后发出未处理 error，使 SACS 以 code 1 退出。现在由 persistence 包创建该 pool，处理死掉的空闲连接、沿用项目连接/查询超时和 pool 上限；活跃查询错误仍正常返回。初始化失败时关闭该 pool。

## 实际故障证明

[harness 证据](R05-process/attempt-5/EVIDENCE.json) 是独立 SACS 子进程、真实本地 HTTP 和专有 PostgreSQL 容器的直接结果。子进程使用生产 bootstrap、v0.6 composition、运行时和 repositories；只在测试 storage port 上设置提交后通知屏障，再由父进程发 SIGKILL。WSGS 是公开合同兼容 peer，不是实际 Provider/设备。

八个场景和两个恢复实例在同一隔离数据库中验证，完整批次 **1/1 PASS**，包含八项故障断言。保留 production **180000ms lease / 30000ms recovery tick**，批次耗时 **224348ms**。恢复时间记录为各用例从批次开始的观测时刻，范围约 191845–223403ms；不能将这些时刻误称为单例恢复耗时或即时恢复 SLA。

| 场景     | 直接断言                                                                                                  |
| -------- | --------------------------------------------------------------------------------------------------------- |
| prepare  | canonical request 已持久化、尚无 HTTP POST 时终止；恢复后一个 POST/一个逻辑 Job                           |
| unsure   | 上游接受、SACS 未收到响应/未保存远端 ID 时终止；同 canonical bytes/key 重发两个 HTTP POST，仍一个逻辑 Job |
| bind     | 远端 ID 已持久化、Analysis 未绑定时终止；恢复只 GET/poll，不再 POST                                       |
| running  | 保存 RUNNING 后 SIGKILL；身份、request/hash 与既有 Job 保留，无重复逻辑工作                               |
| terminal | 终态 result 已持久化、投影尚未写入时终止；恢复直接补投影，无额外 get/post                                 |
| cancel   | 取消意图及 CANCEL_REQUESTED 已存储、回执丢失时终止；恢复仍针对专有 Job，只有公开 CANCELLED 后通过         |
| outage   | actual PostgreSQL restart/reopen；修复后原 SACS PID 不退出，随后恢复该 Job                                |
| late     | 旧 Revision 的迟到终态只记历史；当前 Revision 和完整 Snapshot hash 不变                                   |

两个真实 SACS 实例同时提交同键新 Revision，返回 202/replay 或 409 冲突，只有一个新逻辑 Job。SQL 唯一约束和 lease claim fencing 与 Source runtime 共同生效。PID 生命周期、DB restart/reopen、请求/hash、调用计数、权威终态及清理均在 evidence 中。所有专有数据库、子进程与容器已清理。

## 回归与限制

独立 checkpoint 检查 **1/1 PASS**：保存 channel/id，实际重启专有 PostgreSQL，再由同一 PostgresSaver 读回完全相同的值。另有 persistence、analysis-development、grounding-lifecycle 及 Chromium 控制的 **32/32 tests、4/4 suites PASS**。typecheck、架构、build 和 scoped lint 通过，lint 有 non-null assertion warnings、无 errors。阶段命令与摘要见 [R05-validation.json](R05-validation.json)；控制台未自动存成原始日志的检查明确标记 console capture，不伪造 raw output hash。

重复验证入口为 `pnpm test:v06:process`（约四分钟）和 `pnpm test:v06:checkpoint`。harness 只创建自己命名的 PostgreSQL 容器，固定私有 loopback host port 以支持 restart，最终删除其数据 volume；不继承真实数据库/服务设置，不修改共享部署。

失败尝试保持独立：attempt-1 是 Jest 跨 realm JSON 对象触发严格 plain-object 检查，测试改用文本解析；attempt-2 的取消 peer 过早发布终态，不符合待确认故障窗口，改成显式延迟终态；attempt-3 在 restart 后记录端口不可用，原随机端口设置改成固定端口，并修复清理失败时丢失报告；attempt-4 才直接复现 production checkpoint pool 退出。所有失败不能计为 PASS，见 receipt 中的 earlierAttempts。

这些证明限定 SACS 消费者进程及专有数据库恢复，不代表 PostgreSQL HA、跨地域切换、生产压力/容量、真实 WSGS 或 SDAR/device 资格。真实源的适用恢复/取消仍需 R06 当前授权用例。
