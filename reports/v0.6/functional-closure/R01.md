# R01 会话路由与候选执行隔离

R01 完成 FC-01–FC-06。普通对话不再因“改为”“这个位置”“第一个”等通用词创建 Grounding；已绑定分析的窄展示/选择命令仍复用当前来源。所有 SDAR mutable dispatch 在分类之后、任务 claim/A2A 调用之前重新检查来源，历史上下文和模型输出不能产生执行授权。

## 实现与行为

`v06-grounding-analysis.ts` 读取当前 principal/Chat 的 Analysis，核对 Revision、持久化 execution、合同身份及公开结果/hash。匹配源的窄命令才跳过正常分类。过期候选的读取和已有严格选择校验保持原有行为。

`ConversationApplicationService` 对 new_task、grounded_task、follow_up、cancel 统一调用来源检查；即使受控模型返回 `SDAR_TASK`，仍不能绕过。Task 引用来自授权目录和完整标识匹配，不接受客户端/模型提供的来源标志。

在当前只读世界 Source 下，缺少独立来源证明的 mutation 返回澄清。用户可明确当前授权 Task 编号，或以“创建独立任务：巡检仓库”启动与历史候选无关的新任务。既有 Task 确认/继续/取消命令保持独立控制语义。新任务的模型改写必须与用户独立请求或其确切正文一致，防止替换目标。普通聊天、只读 Task 查询和 utility 不进入 mutation guard；无世界 Source 和旧 1.0/1.1 组合保留原流程。
